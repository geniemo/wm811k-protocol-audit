# 프로세스 리포트 — WM-811K 평가 프로토콜 감사

`README.md`가 "무엇을 만들었고 숫자가 무엇인지"를 보여준다면, 이 문서는 그 뒤에 있는 "왜 이렇게 설계했고, 무엇이 예상과 달랐고, 무엇을 배웠는지"를 정리한 것입니다. 결과 표·그림·재현 명령은 README에 이미 있으므로 여기서는 반복하지 않고, 필요한 최소한의 숫자만 다시 인용합니다.

## 1. 한 줄 정의와 배경

이 프로젝트는 모델·학습 절차·seed를 전부 고정한 채 **평가 프로토콜(분할 방식·클래스 구성·표본 선택)만** 바꿔가며, WM-811K 웨이퍼맵 결함 분류에서 보고되는 성능이 프로토콜 때문에 얼마나 움직이는지를 측정합니다. 측정 대상은 모델이 아니라 **프로토콜이 성능 숫자에 기여하는 크기**입니다.

동기는 배포 상황의 비대칭에서 나왔습니다. 실제 팹에서 분류기는 학습 시점에 본 적 없는 **새 lot**의 웨이퍼를 판정해야 합니다. 그런데 공개된 WM-811K 프로젝트들은 검증 방식이 서로 다릅니다.

- [arXiv:2605.14255](https://arxiv.org/abs/2605.14255)는 lot 단위 분할을 **채택**하지만, lot을 섞는 분할과 직접 비교한 격차는 측정하지 않습니다. 이 프로젝트가 채우려는 빈틈이 정확히 여기입니다 — "lot 분할이 더 안전해 보인다"는 것과 "그래서 정확히 얼마나 차이가 나는가"는 다른 질문입니다.
- [judahobi/Defect_KAN](https://github.com/judahobi/Defect_KAN)은 층화 70/15/15 분할에 `none`을 15,000장으로 캡핑합니다.
- [fr407041/WM-811K_semiconductor_wafer_map_pattern_classified](https://github.com/fr407041/WM-811K_semiconductor_wafer_map_pattern_classified)는 결함 클래스만 25,519장을 추려 랜덤 60/15/25로 나눕니다.

세 저장소 모두 합리적인 선택이지만, 서로 다른 프로토콜이 만든 숫자를 그대로 비교할 수는 없습니다. 이 문서는 어느 쪽이 맞다고 주장하지 않고, **프로토콜 차이의 크기**를 같은 모델·같은 학습량으로 직접 재봅니다.

## 2. 실험 설계와 그 근거

값 자체는 README의 "프로토콜 카드"에 있으니, 여기서는 **왜 그 값인지**만 적습니다.

| 결정 | 왜 |
|---|---|
| 학습량을 **고정 8,000 gradient step**으로 (에폭 아님) | 에폭 고정은 표본 규모와 교락됩니다. cap을 줄이면(C3) 1 에폭이 몇 step밖에 안 되므로, "에폭 수를 맞췄다"는 것이 실제로는 셀마다 전혀 다른 연산량을 의미하게 됩니다. step을 고정하면 모든 셀이 정확히 같은 연산량으로 비교됩니다. |
| 리사이즈를 **중심 정렬 nearest-neighbour**로 | 웨이퍼맵 픽셀값 {0,1,2}는 die 없음/정상/불량이라는 **이산적 의미**입니다. bilinear 등 보간을 쓰면 0과 1 사이의 0.4 같은, 데이터에 존재하지 않는 값을 만들어냅니다. 존재하지 않는 정보를 만들지 않는 것이 nearest-neighbour를 고른 이유입니다. |
| 입력을 **3채널 one-hot**으로 (스칼라 1채널 아님) | 스칼라 채널로 넣으면 "die 없음(0) < 정상(1) < 불량(2)"이라는 서열을 모델에 강제하게 됩니다. 세 상태 사이에는 그런 순서가 없으므로, 순서를 강제하지 않는 one-hot을 택했습니다. |
| **lot-disjoint gold 테스트셋을 1개만, 한 번만 carve** | 만약 gold셋이 없다면 셀마다 자기 테스트셋으로만 채점하게 되고, 그러면 축(A)을 바꿀 때 **학습 데이터와 채점 기준(야드스틱)이 동시에 바뀝니다** — 성능 변화가 프로토콜 때문인지, 애초에 다른 잣대를 쓴 것인지 구분할 수 없습니다. 그래서 모든 셀을 (1) 자기 테스트셋 기준 as-reported, (2) 공통 gold셋 기준 on-gold, 두 열로 나란히 보고합니다. 이 두 열 구조가 이 프로젝트에서 가장 중요한 설계 결정입니다. |
| cap을 **클래스당 표본 수 규칙**으로 (절대 개수 아님) | 표본 선택 축(C)은 "클래스당 최대 N장"이라는 규칙으로 정의했습니다. 만약 대신 "결함만 25,519장"처럼 절대 개수·클래스 부분집합으로 정의했다면, 그건 사실상 클래스 구성 축(B, none 포함 여부)을 다시 조작하는 것과 같아져서 **B와 C 두 축이 서로 독립이 아니게 됩니다**. 두 축을 분리해서 각각의 기여도를 따로 말하려면, cap은 클래스 구성이 이미 정해진 뒤에 그 안에서만 작동하는 규칙이어야 했습니다. 이 문제는 실행 전 설계 검토 단계에서 확인되어, 첫 run을 돌리기 전에 "클래스당 cap"(C1 없음 / C2 5,000/class / C3 클래스 구성 적용 후 pool 내 최소 클래스 수)으로 정리했습니다. |

세 축의 적용 순서도 고정했습니다: **pool → B(클래스 필터) → C(cap, seed) → A(분할, seed) → 학습(seed) → 평가**. 순서를 고정한 이유도 같습니다 — 순서가 바뀌면 예를 들어 cap을 분할 후에 적용하는 것과 분할 전에 적용하는 것이 서로 다른 실험이 되기 때문입니다.

## 3. 진행 과정 (실제 순서)

1. **데이터 확보** — MIR 공식 배포본(`http://mirlab.org/dataSet/public/MIR-WM811K.zip`, 로그인 불필요, 329 MB) → 압축 해제 후 `WM811K.pkl` (2.02 GB).
2. **EDA** — 라벨 분포, 원본 분할의 lot 겹침, lot 구조, 정확 중복, 맵 크기 분포를 먼저 측정 (4절 참고). 이 단계에서 나온 사실들이 이후 모든 설계 결정의 근거가 되었습니다.
3. **고정 전처리** — pkl → 정규화된 64×64 배열 + 메타데이터(`convert_data.py`), 리사이즈·인코딩 규칙 확정.
4. **분할 함수** — gold carve, A1~A4 분할, B 클래스 필터, C cap 규칙.
5. **모델 + 학습 루프** — SmallCNN, 8,000-step 고정 학습.
6. **러너** — 57 run(18셀×3seed + 보조 A4×3seed) 순회, 재개 가능한 `results.csv`.
7. **분석** — 표·그림 생성.

이 순서를 지킨 이유는 뒤 단계의 실수가 앞 단계로 전파되지 않게 하기 위해서입니다 — 예를 들어 분할 함수의 lot-disjoint 성질은 EDA에서 확인한 lot 구조를 알고 나서야 제대로 테스트할 수 있었습니다.

**지켰던 규율**

- **TDD**: 71개 테스트(`pytest --collect-only` 기준 — `test_analyze` 6, `test_data` 24, `test_diagnostics` 6, `test_metrics` 5, `test_preprocess` 8, `test_run` 6, `test_splits` 11, `test_train` 5)가 전처리 규칙, 분할의 lot-disjoint/층화 성질, cap 규칙, 지표 정의(sklearn과의 일치), 누수 진단(brute-force 대조)까지 커버합니다. 코드를 먼저 정당화하지 않고, 성질을 먼저 테스트로 적은 뒤 구현했습니다.
- **단계별 독립 리뷰**: 21개 커밋이 "패키지 스캐폴드 → 전처리 → 분할 → 지표 → 학습 루프 → 러너 → 진단 → 실행 → 분석 → 문서"로 잘게 나뉘어 있고, 각 단계가 그 자체로 테스트 가능한 단위였습니다.
- **셀 단위 재개 가능한 결과 저장**: `results/results.csv`는 이미 완료된 `run_id`를 건너뛰고 이어서 실행되도록 만들었습니다. 57개 run 중 하나가 크래시해도 전체를 다시 돌릴 필요 없이 그 한 run만 다시 실행하면 됩니다 — GPU 작업 중간에 문제가 생겨도 손실이 run 1개로 제한됩니다.

## 4. 데이터에서 확인한 사실 (EDA)

아래는 모두 `results/eda.json` / `results/tables/eda.md`에서 직접 측정한 값입니다. 일부는 통념과 반대이거나, 공개 자료 어디에도 명시되어 있지 않아서 직접 재봐야 했던 것들입니다.

- **라벨 172,950장 = Training 54,355 + Test 118,595** — Test가 Training보다 **큽니다.** 보통 "학습셋이 더 크다"고 가정하기 쉬운데 반대입니다.
- **원본 분할은 lot-disjoint입니다** — 두 집합에 걸친 lot이 0개. 그런데 **유사-시간 분할**이기도 합니다 — Training lot 번호 1~46,729(중앙값 36,921), Test lot 번호 40,328~47,542(중앙값 44,422), 순서상 교차 구간은 16개뿐입니다. 이 사실은 공개 문헌 어디에도 나와 있지 않아서 직접 측정했습니다(단, lotName이 실제 시간 순서라는 문서 근거는 없으므로 "유사"로만 표기합니다).
- **층화되어 있지 않습니다** — Test의 93%가 `none`, Training은 약 68%가 `none`입니다.
- **10,762개 라벨 lot, lot당 라벨 웨이퍼 중앙값 23장** — 라벨링이 lot 단위로 이루어졌다는 뜻입니다.
- **결함 웨이퍼의 83%가 "같은 lot에 결함이 2장 이상"인 lot에 속하고, 그런 lot의 51.5%는 결함 클래스가 하나뿐입니다** — 랜덤 분할에서 형제 웨이퍼 누수가 구조적으로 성립할 조건이 실제로 존재합니다. (이 구조가 있기 때문에 5절의 "누수 효과가 작다"는 결과가 더 의미가 있습니다 — 누수가 일어날 조건 자체는 있었는데도 효과가 작았다는 뜻이기 때문입니다.)
- **6,502/172,950장(3.76%)이 정확 중복**이고, 중복 그룹의 99.6%가 여러 lot에 걸치며 6,304건이 `none`입니다 — **lot-disjoint 분할을 해도 `none` 중복은 남습니다.**
- **346개의 서로 다른 맵 shape, 중앙값 33×33**, 64를 넘는 쪽이 있는 맵은 2.01%뿐 — 대부분 업샘플 대상입니다.

## 5. 결과와 해석

(전체 18+1셀 표, 그림, 축별 기여도 표는 README 참고. 여기서는 핵심 숫자와 그 의미만.)

**대표값**: 가장 엄격한 조건(`A3-B1-C1`, lot-group 분할·9클래스·cap 없음)의 공통 gold셋 9-class macro-F1은 **0.839 ± 0.005**(3 seed). 배포 상황에 가장 가까운 대표 숫자입니다.

세 조작 축의 효과를 같은 두 지표(own macro-F1 / gold defect-F1)로 나란히 놓으면:

| 축 | own 지표 격차 | gold 지표 격차 | 의미 |
|---|---:|---:|---|
| 분할(A2 랜덤 → A3 lot-group) | +0.007 | −0.003 | 매우 작음 |
| 표본 선택(C1 cap없음 → C3 balanced) | −0.186 | −0.225 | 한 자릿수 위 크기 |
| 클래스 구성(A1 원본, own vs gold 9-class) | own 0.440 | gold 0.659 | 같은 가중치, 다른 테스트셋 |

**분할 축**은 두 지표 모두에서 격차가 작습니다. **표본 선택 축**은 두 지표 모두에서 훨씬 크게, 그리고 일관된 방향으로 움직입니다 — 즉 이 실험에서 "프로토콜이 성능에 미치는 영향"의 크기는 축마다 다르고, 표본 선택이 분할보다 훨씬 지배적입니다.

**A1(원본 분할)** 자체도 흥미로운 사례입니다 — 같은 가중치를 자기 테스트셋으로 채점하면 own macro-F1 0.440인데, 같은 가중치를 gold셋으로 채점하면 0.659(9클래스), defect-F1만 좁히면 0.775까지 올라갑니다. 모델이 바뀐 게 아니라 **어떤 테스트셋으로, 어떤 지표로 채점했는지**가 바뀐 것뿐입니다. 이 프로젝트가 하려는 말을 가장 압축적으로 보여주는 사례입니다.

## 6. 가설이 반박된 두 지점 — 이 보고서의 핵심

설계 단계에서 세운 예측 두 가지가 실측과 어긋났습니다. 그대로 적습니다.

### 6-1. "lot 혼입이 성능을 크게 부풀릴 것이다" → 부분적으로 반박

**가설**: 랜덤 분할은 같은 lot의 형제 웨이퍼가 학습·테스트에 함께 들어가므로(리키지), 채점이 부풀려질 것이다.

**결과**: 랜덤(A2) − lot-group(A3) 격차는 **+0.007**(3 seed 페어드 평균, sd 0.0031). 부호는 세 seed 모두 일관됩니다(+0.0105 / +0.0052 / +0.0051). 하지만 이 두 셀 자체의 seed 표준편차(A2: 0.0039, A3: 0.0043)의 2배 안쪽입니다. n=3에서 이 크기의 격차는 **"0이다"라고 말할 근거도, "0이 아니다"라고 말할 근거도 부족합니다** — 정확히는 **누수 효과를 대략 ≤0.01 정도로 상한 지을 수 있을 뿐**입니다. "효과가 없다"고 쓰지 않고 "이 정도 크기 이상은 아니다"라고 쓰는 것이 정직한 표현이라고 판단했습니다.

**메커니즘도 확인했습니다.** 각 테스트 웨이퍼에서 가장 가까운 학습 웨이퍼까지의 해밍 거리(64×64, one-hot 기준) 중앙값은 랜덤 분할 361, lot-group 분할 355로 **거의 같습니다.** 반면 `lot_share_rate`(랜덤 분할 테스트 웨이퍼 중 같은 lot의 다른 웨이퍼가 학습셋에 있는 비율)는 0.98로, 랜덤 분할이 실제로는 lot을 거의 다 공유합니다. 즉 **lot은 공유되는데, 그렇다고 테스트 웨이퍼가 학습셋에서 유난히 더 가까운 이웃을 찾게 되지는 않습니다** — 공유된 lot 안에서도 웨이퍼 사이의 실제 거리가 그렇게 가깝지 않다는 뜻이고, 이것이 위 결과가 작게 나온 이유로 보입니다.

**해석**: 이 데이터셋·이 모델 규모에서는 서로 다른 논문 간 성능 차이가 분할 방식의 누수보다 **실제 모델 차이일 가능성이 더 높습니다.** 다만 이것을 "lot 분할 없이 검증해도 항상 괜찮다"로 일반화하면 안 됩니다 — 실제 배포 환경에서는 lot·제품·시기 간 상관이 여전히 다른 종류의, 아마 더 큰 리스크이며, 이 정적 데이터셋 하나에서 그 효과가 강하게 드러나지 않았을 뿐입니다.

### 6-2. "Edge-Loc과 Scratch가 헷갈릴 것이다" → 반박

**가설**: Edge-Loc과 Scratch는 둘 다 웨이퍼 가장자리에 붙은 길쭉한 형태의 결함 군집이라, 서로 혼동될 것이다.

**결과**(`A3-B1-C1`, gold 9클래스, 3 seed 합산 confusion — `results/tables/confusion_gold_A3-B1-C1.md`): 실제 지배적인 실패 패턴은 Edge-Loc↔Scratch 혼동이 아니라 **결함이 `none`으로 새는 것**이었습니다. Scratch의 32%, Loc의 25%, Edge-Loc의 22%가 `none`으로 오분류됩니다. 클래스별 recall(%)은 none 100, Edge-Ring 96, Random 95, Near-full 93, Center 83, Edge-Loc 72, Donut 71, Loc 59, Scratch 56.

**해석**: 팹 관점에서 이건 "다른 결함으로 잘못 분류하는" 문제가 아니라 **결함을 놓치는(missed detection) 문제**입니다. 두 문제는 운영상 대응이 다릅니다 — 오분류는 재분류·재검토로 대응하지만, 미탐지는 애초에 알람이 안 뜨는 문제라 검출 임계값이나 클래스 불균형 처리 쪽을 봐야 합니다.

이 두 사례를 굳이 남겨두는 이유는, **예측을 실행 전에 문서에 적어 두었고, 데이터가 그 예측과 다르게 나왔다는 것을 숨기지 않았기 때문에** 나머지 결론들도 신뢰할 수 있다고 생각하기 때문입니다.

## 7. 한계 (정직하게)

- **lot-disjoint 분할도 배포 조건의 상한이 아닙니다.** 새 제품 도입이나 레이아웃 변경으로 인한 분포 변화는 이 실험이 포착하지 못합니다. lot-group 분할은 "같은 제품·시기 안에서 다른 lot"을 흉내 낼 뿐입니다.
- **8,000-step 고정 학습량은 cap 축(C)에서 중립적이지 않습니다.** `A3-B1-C1`(약 110,665 웨이퍼)은 약 18.5 에폭, `A3-B1-C3`(약 857 웨이퍼)는 약 2,400 에폭에 해당합니다 — cap 효과에는 "데이터가 적다"는 것과 "그 적은 데이터를 훨씬 더 많이 반복한다"는 것이 뒤섞여 있습니다. 다만 이것이 −0.225 자체를 설명하지는 못합니다: `A3-B1-C3-s0`의 gold defect-F1은 step 1,000의 0.626에서 step 8,000의 0.606으로 평평하거나 오히려 소폭 하락하고, training loss는 이미 step 3,000경 ~1e-3, step 6,000 이후 ~1e-4까지 떨어집니다 — 학습이 부족한 것이 아니라 이미 수렴(사실상 암기)한 상태입니다. 검증셋 기반 조기 종료를 했더라도 ≈0.63 수준이었을 것이고, 이는 여전히 C1보다 ≈0.20 낮습니다. 이 비대칭이 −0.225를 만든 것은 아니지만, 존재한다는 사실은 남겨둡니다.
- **n=3 seed는 작은 효과를 확정하지 못하고 상한만 지어줍니다.** 6-1절의 +0.007이 대표적인 예입니다.
- **Donut(gold 111장)과 Near-full(gold 30장)은 표본이 너무 적어** 클래스별 F1에 대해 단정적인 결론을 내리지 않습니다.
- **패턴→공정 원인 매핑(Scratch=취급 스크래치 등)은 공개 문헌의 일반론이지, 특정 팹의 지식이 아닙니다.**
- **선행 연구 검색은 웹·arXiv·GitHub 범위로 한정했습니다.** "확인되지 않음"이지 "존재하지 않음"이 아닙니다.

## 8. 배운 것 / 다음 단계

**전이 가능한 것들**

- 숫자를 믿기 전에 "이 숫자는 어떤 조건에서 나왔는가"를 먼저 묻는 습관 — A1의 own 0.440 vs gold 0.659 사례가 이 습관이 왜 필요한지 보여줍니다.
- **제대로 경계 지어진 부정적 결과(negative result)도 쓸모 있는 결과**라는 것 — 6-1절처럼 "0이라고 단정할 수 없지만 대략 이 이하로 상한 지을 수 있다"는 표현이, "차이 없음"이라는 과장된 표현보다 훨씬 정직하고 실무적으로 유용합니다.
- **공통 held-out 셋이 있어야 프로토콜 비교가 의미를 가진다**는 것 — gold셋 없이는 축을 바꿀 때마다 야드스틱도 같이 바뀌어서, 애초에 "무엇이 변했는지"를 말할 수 없습니다.

**다음 단계** (설계 문서 §9 기준)

- 라벨 데이터는 전체(811,457장 중 172,950장)의 약 21%뿐이고, 나머지 약 79%는 미라벨입니다. 이 79%를 이번에 고정한 프로토콜(gold셋, 지표, 리사이즈·인코딩 규칙) 위에서 준지도 학습에 활용하는 것이 다음 확장입니다.
- 패턴 분류 위에 **에이전트 기반 근본 원인 진단 레이어**를 얹어, 검증 가능한(falsifiable) 규칙 체크로 "이 패턴이 왜 나왔는가"에 대한 가설을 좁혀가는 방향을 검토 중입니다.

## 부록 — ResNet-18 강건성 확인

9개 run이 모두 완료되었습니다. 파라미터가 46배(242,345 → 11,173,449)인 `ResNet18Adapted`를 **동일한 하이퍼파라미터**로 학습한 결과, 절대 성능은 모든 셀에서 높아졌지만(gold defect-F1 +0.04~0.06) **프로토콜 격차 자체는 거의 변하지 않았습니다.**

| 격차 | 지표 | SmallCNN | ResNet-18 |
|---|---|---:|---:|
| 분할 (랜덤 − lot) | as-reported macro-F1 | +0.007 | +0.007 |
| 분할 (랜덤 − lot) | gold defect-F1 | −0.003 | −0.000 |
| 표본 cap (119장 − 전체) | as-reported macro-F1 | −0.186 | −0.211 |
| 표본 cap (119장 − 전체) | gold defect-F1 | −0.225 | −0.242 |

분할 격차는 두 모델에서 소수점 셋째 자리까지 같고, 표본 cap 격차는 큰 모델에서 오히려 조금 더 커집니다. 따라서 §6에서 정리한 "이 데이터셋에서는 lot 누수보다 표본 선택이 훨씬 큰 교란 요인"이라는 결론은 **모델 용량이 작아서 나온 인공물이 아닙니다.** 한계도 함께 적어두면, 두 모델은 같은 학습 예산(8,000 step)과 같은 입력 해상도(64×64)를 공유하므로 여기서 확인한 불변성은 파라미터 수에 대한 것이지 아키텍처 계열 전반에 대한 것은 아닙니다.
